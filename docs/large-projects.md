# 大项目导入与存储

原来的 500 个文件 / 50 MiB 是应用的保护性上限，并非 pdfLaTeX 的限制。当前实现将边界统一，并减少大图片在保存、备份和同步过程中的重复分配。

## 当前边界

| 项目                                                    | 上限     |
| ------------------------------------------------------- | -------- |
| 实际导入文件                                            | 5,000 个 |
| 文件夹                                                  | 5,000 个 |
| 项目文件原始字节总量                                    | 250 MiB  |
| 单个文件                                                | 128 MiB  |
| 导入 ZIP 本身                                           | 250 MiB  |
| 编译输出 PDF                                            | 128 MiB  |
| WebDAV JSON 快照（包括 Base64、元数据与同步的 AI 历史） | 384 MiB  |

界面使用 MB 简写，实际按 1024 × 1024 字节计算。桌面与共享前端读取 `apps/desktop/project-limits.json`。移动原生桥另有对应的序列化大小检查。

ZIP 先排除 `__MACOSX`、`.git`、`node_modules`、构建目录与常见临时输出，再统计真实文件；目录条目不占用文件数。解压逐块累计实际大小，达到边界立即停止，不只相信 ZIP 中声明的长度。保留路径检查、重名检查和外部文件冲突保护。

## 已实现的优化

- IndexedDB 升至版本 3。图片、PDF 等二进制内容按项目与 SHA-256 独立保存为 Blob；项目和备份只保存引用。编辑正文时不重复写入未变化的资源。删除备份或资源后，只回收没有其他备份引用的资源。
- 项目、资源和恢复记录使用事务提交。写入失败时不留下指向缺失资源的新项目记录。旧内联二进制数据可直接读取，在下次保存时迁移；旧备份仍可恢复。
- 桌面保存逐块计算摘要，跳过未变化的文件，不同时保留所有待写二进制文件的解码副本。网页关联目录也跳过未变化文件。外部修改仍会阻止覆盖。
- Base64 转换分块处理；桌面 PDF 通过二进制数组返回，不展开成 JavaScript 数字数组。
- EPS 转换缓存经过内容和输出校验；来源变化或缓存损坏时重新转换。最多保留 32 项 / 128 MiB，缓存不可用不阻断正常编译。
- WebDAV 分块生成上传 JSON、计算摘要和保存同步前备份，下载逐块解码并检查大小；保留现有 JSON 格式、ETag 冲突检查和双向同步语义。

## 仍需注意的范围

这不是无限容量或完整的按需加载架构：工作区目前仍会读取项目内容，编译仍创建完整的临时文件快照；WebDAV 仍上传完整项目快照，并非只上传变化文件。连接的服务也可能设置更低的请求体上限。浏览器存储空间、设备内存和移动 WebView 能力仍会影响可用容量。

版本 3 的本地资源记录不能由旧版的 IndexedDB 实现直接读取。需要回退旧版本时，先在新版导出 ZIP，或从原关联项目文件夹重新导入；不要让新旧版本同时使用同一个应用数据目录。

本轮在 Windows / Chromium 验证了 602 文件 + 65 MiB 资源的 ZIP 导入、保存、备份、导出、重启读取和实际 pdfLaTeX 编译，以及 603 文件 + 81 MiB 资源的 WebDAV 往返同步（JSON 超过旧 100 MiB 上限）。这些是代表性回归样例，不等于所有设备均完成 250 MiB 极限测试。移动桥的上限已对齐，但本轮没有 Android/iOS 真机或 macOS 验收。

本轮按要求只修改与测试源码，不生成安装包或发布 Release。
