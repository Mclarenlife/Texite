# AI 助手

点击顶栏 **AI 助手** 打开应用内浮动窗口。拖动标题栏移动，拖动右下角调整大小，也可最小化；窗口不再占用编辑器或 PDF 的布局宽度。

- **Agent**：桌面版连接本机 Agent CLI，通过 Codex app-server 或 ACP 协议读取和修改文稿。Codex 适配器还支持调用当前项目编译器检查错误；ACP 适配器目前提供文本读写。
- **对话 → Agent CLI**：使用所选本机 CLI，只读取文稿和诊断，不提供写入或编译工具。
- **对话 → 自定义 API**：填写 API 地址、模型 ID 和 API Key，支持 OpenAI 兼容的 Chat Completions 流式接口。可以填写 `/v1` 基础地址或完整 `/chat/completions` 地址；本机 HTTP 服务支持 `localhost`、`127.0.0.1` 和 `::1`，其他服务使用 HTTPS。此模式没有文件操作工具。

桌面版自定义 API 由主进程请求，密钥通过系统加密保存；系统加密不可用时只保留在本次进程内。设置读取接口不返回密钥，更换 API 地址会清除旧密钥，也可手动清除。网页版支持自定义 API 对话，服务需允许 CORS；密钥只保存在内存中，刷新后重新填写。API 对话会发送当前文件前 30,000 个字符、有限的编辑器上下文和最近对话，长文稿不会自动全部发送。

## 0.10：选区、会话与多个连接配置

### CLI 连接生命周期

助手连接状态旁的断开按钮会结束 Texite 启动的 CLI 及其子进程，不影响终端中独立启动的其他 CLI。正在执行的任务会停止，已保存的修改和撤回记录保留。关闭助手浮窗只隐藏界面；彻底退出 Texite 才会关闭它管理的 CLI。

连接设置提供空闲自动断开：默认 5 分钟，可选从不、1、5、10、30 分钟。计时从连接成功或任务结束后开始，任务进行中不自动断开。无论手动还是空闲断开，下一次发送指令都会自动启动所选 CLI 并连接；旧会话保留，重新连接时发送有限历史上下文。CLI 本身在未断开期间可能联网，此设置不是联网隔离或代理配置。

AI 浮窗顶栏中央切换 Agent / 对话。工具栏左侧是「对话记录」、新建和清空按钮；记录列表按当前项目与模式分别管理。点击列表切换会话，关闭应用后仍可恢复。清空操作需要确认，会删除该项目当前模式下的所有会话和对应 AI 撤回记录，不会撤销已经应用的文稿修改。新建空会话同样可以清空。

编辑器选中文字后，输入框上方文件名旁显示起止行、字位置。同一行显示「第 2 行，第 1–2 字」，跨行显示起止位置；显示按 Unicode 字符计数，工具校验使用 UTF-16 偏移。将「苹果」选中后在 Agent 输入框发送「改写成英文」，模型会优先处理该选区，应用拒绝超出选区的修改。对话模式会优先参考选中文字，但不会修改文稿。发送后再手动改动文稿时，仍有原文冲突保护。

API 设置可以新增多套配置，各自保存名称、地址、模型及密钥。输入框左下角切换已保存的 API。切换服务会继续当前对话，模型只获得当前会话的有限历史；要开始独立上下文，请新建对话。桌面版各密钥独立进行系统加密，网页端仅在内存保留密钥。变更某一配置的服务地址会清除其旧密钥，不影响其他配置。

### Agent CLI 接入方式

通用入口显示为「Agent CLI」。在连接设置中选择 CLI 类型、程序与参数，任务结束后可以随时切换；各类型的配置分别保存。已有 Codex 设置会继续兼容。

| 类型 | 启动方式 | 准备工作 |
| --- | --- | --- |
| Codex CLI | 现有 app-server 适配器 | 安装并在终端登录；留空自动查找程序 |
| Claude | `claude-agent-acp` | 安装对应 ACP 适配器并完成 Claude 登录 |
| Qwen Code | `qwen --acp` | 安装支持 ACP 的 Qwen Code，并在终端登录 |
| MiniMax / DeepSeek | `opencode acp` | 先在 OpenCode 配置对应模型服务，填写 CLI 返回的完整模型 ID |
| 自定义 | 可执行程序 + JSON 参数数组 | 程序必须支持 ACP v1 标准输入输出与编辑器文件读写 |

这不是把任意终端 CLI 都当作同一种协议，也没有内置这些第三方 CLI。MiniMax / DeepSeek 预设通过 OpenCode 提供服务，不代表存在同名官方 CLI。当前 ACP 支持初始化、会话、流式回复、编辑器文本读写、模型切换（服务端提供时）与取消；不提供终端执行，不自动批准原生 shell/文件权限请求。不能使用编辑器文件读写接口的 CLI 工具会被拒绝，界面会显示失败原因。

ACP 进程的工作目录是 Texite 数据目录中的空工作区，文稿通过编辑器接口读取和修改，修改继续经过选区、原文、恢复记录校验。外部 CLI 本身是当前用户权限的本机进程，并不具备额外操作系统沙箱，因此仅配置你信任的 CLI。认证和模型费用由对应 CLI 管理，Texite 不搬运其登录令牌。CLI 特有的 MCP、插件、工具或 shell 能力不由 Texite 代理。

原生连接和 ACP 各自按项目、会话、模型、模式隔离运行会话。重启或更换 CLI 后会创建新的远端会话，并提供当前对话最近若干轮的有界历史，较早内容不会全部发送。

本版本使用确定性的 ACP 子进程与真实 Electron IPC 回归验证连接、流式回复、编辑器修改、只读拒绝、范围限制、取消和历史隔离；没有声称已通过所有厂商 CLI 的真实付费模型联调。具体兼容性取决于所安装的 CLI / 适配器版本。

协议来源：[ACP v1](https://agentclientprotocol.com/protocol/v1/initialization)、[Qwen ACP 架构](https://qwenlm.github.io/qwen-code-docs/en/developers/architecture/)、[OpenCode ACP](https://opencode.ai/docs/acp/)。

## 光标、选区与插入工具

源码编辑器内点击光标或选择文字后，出现行内 AI 输入框；也可按 **Alt + Enter** 打开。输入指令后自动转到 Agent，未连接时尝试连接所选 Agent CLI。空选区表示在光标处插入，有选区则只允许替换选中文字。应用校验文件、UTF-16 字符范围和原文，阻止越界修改及覆盖任务期间的手动编辑。修改仍可以查看差异和整次撤回。

右键打开插入工具，可指定表格行列数、输入公式、选择项目图片或导入 PNG/JPEG/PDF。导入的图片保存在项目 `assets` 目录；插入图片时按需在当前文件导言区加载 `graphicx`，子文件没有导言区时提示在主文件加载。插入可通过编辑器撤销。

自动补全涵盖常用命令与数学符号、成对环境、文献键、项目标签、源文件和图片路径。输入相应 LaTeX 命令会触发推荐，也可用 **Ctrl + Space** 主动调用。

## Codex CLI 首次连接

先安装 Codex CLI 并执行 `codex login`。Codex 连接使用本机认证，Texite 不保存其登录令牌。自动查找 PATH 和常见 Codex 安装位置；未找到时通过“选择 Agent CLI”指定可执行文件。模型列表来自当前账户。

此前在 Windows 上验证的协议版本为 `codex-cli 0.162.0-alpha.17.2`。动态工具属于实验性接口；其他版本可能不兼容。macOS 具有对应的进程和路径支持，尚未进行本机实测。网页版不能直接启动本机 Codex。Codex 不随 Texite 安装包重复打包。

AI 推理需要联网，并遵循本机 Codex 账户或 API 的使用额度。当前文件名、选中文字、AI 实际读取的项目文件及编译日志会发送给模型；普通编辑和 LaTeX 编译仍可离线使用。此版本是本机连接方案，没有集成产品级登录流程。

## Mac 中“选择程序”应选哪个文件

在终端运行 `command -v codex`，在文件选择窗口用 `Command+Shift+G` 打开输出路径所在目录，选择 `codex` 文件，然后连接。可以先用 `codex --version` 确认该命令可运行。实际路径取决于安装方式，请以终端输出为准。

`ChatGPT.app` 和 `Codex.app` 本身是应用包目录。0.6.0 若直接选择应用包，可能报 `spawn … .app EACCES`；重新选择终端查询到的 CLI 文件即可替换错误路径，终端已完成的登录通常无需重做。当前开发版在保存路径前检查文件类型、执行权限及 Codex 版本，并为 Mac 的 npm/nvm 启动器补充 Node 搜索路径。

## 编辑与恢复

- **直接编辑**：AI 工具读写当前编辑器缓冲区，包含尚未保存到磁盘的修改。每次写入携带完整原文，原文不一致时拒绝覆盖。
- **只读对话**：不向模型提供写入或编译工具，并在主进程与编辑器两处拒绝执行；允许读取文稿及已有诊断。
- **查看差异**：展示本次任务每个文件的新增、删除内容。多次修改同一文件合并为从任务开始到结束的差异。
- **撤回整次修改**：先查看差异再点击撤回；保留 AI 修改前后两份内容和任务记录。只撤回仍与 AI 结果一致的文件，有后续手动修改则整次拒绝。AI 新建且未被再次修改的文本文件会删除，已有文件恢复原文。
- **停止**：中断模型回合，并取消由 AI 发起的编译。已经提交的修改和备份保留，可查看或撤回；正在提交的本地保存事务会完成。

项目源码与 AI 恢复记录在同一个 IndexedDB 事务中提交，失败则不应用修改。磁盘同步随后串行执行，并检查外部修改；同步失败时保留本地版本和恢复记录。磁盘写入逐文件原子替换，不保证整个文件夹的原子事务。

AI 记录按项目保存，重启后可以查看和撤回；不会随普通历史自动清理，也不包含在项目 ZIP 中。每项目记录上限约 12 MB，超限拒绝新的修改，可导出项目并导入为新项目继续。清理应用数据会删除记录。CLI 会话在当前连接期间复用；重启或断开连接后建立新会话，并提供当前对话的有界历史。

## 实现边界

调用链：`AIPanel → useAI → Electron IPC → CodexClient → 本机 app-server`。模型反向调用以下工具，经 IPC 回到编辑器操作实际状态：

| 工具                     | 用途                                 |
| ------------------------ | ------------------------------------ |
| `texite_list_files`      | 获取项目文件、主文件与当前引擎       |
| `texite_read_file`       | 读取最新文本                         |
| `texite_apply_changes`   | 带原文校验的批量修改或新建           |
| `texite_compile`         | 编译当前项目、更新 PDF、返回实际结果 |
| `texite_get_diagnostics` | 获取最近的编译日志和错误位置         |

不开放 shell、原生文件编辑、外部 MCP 服务、浏览器或联网搜索工具。线程不关联本地执行环境，编辑任务使用应用数据目录中的隔离工作区，文稿只通过 Texite 工具访问；原生执行与文件修改审批一律拒绝。保留 Codex 调用动态工具所需的 code-mode host。外部 MCP 名称含协议无法兼容的字符时拒绝连接，避免无法可靠禁用外部工具。

目前不提供 AI 删除/重命名文件、资源图片生成、远程后端、商业登录或外部 Codex 控制 Texite 的独立 MCP 服务。

## 验证

`pnpm test` 包含修改冲突、选区边界、原文备份、整次撤回、磁盘外部改动、只读与中断协议、API 流解析和加密设置测试；`pnpm test:e2e` 包含浮动窗口、模式切换、行内编辑、自动补全、右键插入、API 对话、编译联动、重载后恢复、存储失败和并发修改测试，使用确定性的模拟模型。`node scripts/smoke-chat-desktop.cjs` 通过真实 Electron IPC 和本机 HTTP 测试服务验证 API 对话与系统密钥加密，不调用真实付费模型。

`node scripts/smoke-ai.cjs` 是显式运行的真实模型测试，使用当前本机登录和额度，仅发送隔离测试文稿，验证读取 → 修改 → 内置中文 pdfLaTeX 编译。不会在普通测试或 CI 中自动调用模型。

## 0.11 对话显示、保存与同步

Agent 与对话模式均渲染 Markdown（标题、列表、表格、引用、代码块和 `$...$` / `$$...$$` 数学公式），代码可一键复制；窗口可从任意边或角拖动缩放。

桌面旧记录自动迁移到独立用户文件。默认位置为 Windows `%APPDATA%/texite/ai-history` 或 macOS `~/Library/Application Support/texite/ai-history`。设置 → 同步与存储 → AI 对话数据位置可选择其他文件夹，数据复制进其中的 `Texite-AI-data` 子目录，原目录保留为备份。有冲突的记录不会覆盖。正常重装保留用户数据；手动删除用户目录或深度卸载仍可能丢失数据。

关联 WebDAV 的项目会将对话、对话标题和 AI 修改恢复记录与项目一起同步。仅对话变化也会触发未同步提醒；双端同时修改会保留云端冲突副本。API 密钥、服务配置和 CLI 登录状态不上传。同步设备均需升级至 0.11 或更高版本。对话仍可能含文稿、用户主动输入的敏感信息，请使用自己信任的 WebDAV 服务。

`node scripts/smoke-ai-history-desktop.cjs` 验证旧版迁移、目录切换、浏览器缓存记录移除后重启恢复及代码复制，测试在独立目录中执行，不访问真实用户记录。
